# My Big Quest

A web app that helps students in grades 6–12 find the gaps in their college plan, talk to mentors, and read short tips.
Built from the design prototypes in [`prototype/`](prototype/) (kept for reference only).

## What's in it

| Folder | What it is |
| --- | --- |
| `web/` | React + TypeScript app (Vite): Home, GapFinder quiz, Mentors, Tips, and an `/admin` page |
| `api/` | Fastify API on Node. Runs as a local server in development and as an AWS Lambda in production |
| `shared/` | Quiz content and scoring, mentor seed data, and request schemas, used by both `web` and `api` |
| `infra/` | AWS CDK stack: CloudFront + S3, API Gateway + Lambda, RDS PostgreSQL, Secrets Manager |
| `scripts/devdb.mjs` | Starts a throwaway local PostgreSQL in `.local/` |

### How data is stored

Students don't sign up. Each browser gets a random anonymous id, and the quiz autosaves to PostgreSQL as they answer.

| Table | Holds |
| --- | --- |
| `quiz_sessions` | Answers, grade, which quiz variant (A = one question per page, B = chat), and a gap summary scored on the server |
| `feedback` | The post-quiz feedback form |
| `mentors` | The 10 mentors (seeded from `shared/src/mentors.ts`) |
| `mentor_requests` | Chat requests, with the parent or guardian's email, the only personal data collected |

The A/B variant is picked at random per browser. Add `?v=A` or `?v=B` to the GapFinder URL to force one.

## Run it locally

Needs Node 22+ and the PostgreSQL binaries (`initdb`, `pg_ctl`, `psql`) on your PATH.

```bash
npm install
cp api/.env.example api/.env
npm run db:start
npm run db:migrate
npm run dev:api
npm run dev:web
```

Open http://localhost:5173. The admin page is at `/admin`. Locally, `ADMIN_DEV_BYPASS=true` in `api/.env` opens it without signing in; to test the real Cognito sign-in, see `api/.env.example`.

Tests (the API tests use the local database):

```bash
npm test
```

## Deploy to AWS

```
Browser → CloudFront ─┬─ /*            → S3 (the React app)
                      ├─ /api/admin/*  → API Gateway (checks Cognito sign-in) → Lambda → RDS
                      └─ /api/*        → API Gateway → Lambda → RDS PostgreSQL (private subnet)
```

Lambda and the database are in private subnets with no internet access. There's no NAT gateway, to keep costs down.
The database password is generated by AWS at deploy time; no secrets are stored in this repo.
Database migrations run automatically during each deploy.

One-time setup per AWS account and region (needs admin-level credentials):

```bash
npx cdk bootstrap -c stage=staging
```

Then for each deploy:

```bash
npm run build -w web
cd infra && npx cdk deploy -c stage=staging -c adminEmail=you@example.com
```

`adminEmail` is only needed the first time. It creates that person as the first admin, and Cognito emails them a temporary password.

The deploy prints the site `Url`, the `AdminUrl`, and the Cognito `UserPoolId`.

### Admin sign-in

Admins sign in with Amazon Cognito at `<Url>/admin`. There's no sign-up, so admins have to be invited:

1. Open the Cognito console, then the user pool named `my-big-quest-admins-<stage>`.
2. **Create user**: enter their email and choose **Send an email invitation**.
3. Open the **admins** group and add the user. Only members of this group can use `/admin`.

Or with the AWS CLI:

```bash
aws cognito-idp admin-create-user --user-pool-id <UserPoolId> --username person@example.com --user-attributes Name=email,Value=person@example.com Name=email_verified,Value=true --desired-delivery-mediums EMAIL
```

```bash
aws cognito-idp admin-add-user-to-group --user-pool-id <UserPoolId> --username person@example.com --group-name admins
```

On first sign-in they set their own password. Admins can turn on an authenticator-app code (MFA) in Cognito. To remove someone, take them out of the **admins** group or delete the user.

Behind the scenes, API Gateway checks the Cognito token on every `/api/admin/*` request before the API runs, and the API also checks the user is in the `admins` group.

Use `-c stage=prod` for production. The prod stack turns on database deletion protection, keeps a snapshot if the stack is deleted, and keeps backups for 14 days.

Rough monthly cost for the staging stack at low traffic: about $30–40. Most of that is the `db.t4g.micro` database and the Secrets Manager VPC endpoint.
